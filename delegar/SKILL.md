# Delegar (agy)

Runs `~/.claude/tools/delegar.ps1` (lives in the private claude-config repo, together with the never-send list). Tower and laptop both work if `agy` is installed and signed in.

## When
- Delegate: reading/summarizing many files, inventories, "find where X is", first-pass review of a repo or document set, extracting facts into a table.
- Keep in Claude: any direct write to the vault/memory/repos (agy edits only through a `-Write` worktree that Claude reviews and merges), judgment calls, finance, outward actions, and anything under the never-send list (the script blocks it, exit 2 — don't work around it, ask Lucas). One exception, which Lucas approved on 2026-11-05: rules and memories from `~/.claude` may go out as a filtered scratchpad copy (no settings, `.env` or credentials) that passes `mcp__plugin-authoring__scan_secrets`.
- Web research: `search_web` (Google search) works headless in both modes, but returns only snippets. The URL tool isn't loaded in `-p` mode (tested 2026-11-05, agy 1.5.1), and the default sandbox blocks `curl`. For full pages, pass **`-Web`**: it uses `agy-web.json` (terminal sandbox off) + `--dangerously-skip-permissions` and tells agy to fetch with `curl.exe -sL <url>`. `-Web` requires an **empty `-Dir`** (exit 2 otherwise; use a fresh scratchpad subfolder) and flags exit 5 if anything appears in it. Not write-protected: the `write_file` deny still blocks agy's file tool, but with the sandbox off and auto-approval its shell commands can write anywhere; only the git-check and the empty-dir check would notice. Lucas accepted this (2026-11-05). Verified 2026-11-05: example.com and the claude-code releases page matched a direct fetch. Trial (Lucas, 2026-11-05): if `-Web` never causes problems, drop the sandbox entirely later.
- Video: `read_file` takes a local `.mp4` directly, image and audio, in default mode (verified 2026-11-06 on a 56 s reel, Flash-medium, ~28k tokens, against a local transcript, frames and the post caption). Good for what a video says and shows. Not for animation QA: on a blind test with 7 planted motion defects it found at most 2 per run, passed a wrong list order as clean with High confidence in 4/4, and 4x slowing helped only a white flash (`Documents/agy-outputs/2026-11-06/out-webanim-motion-qa.md`). One page, Flash-medium; custom FPS, stronger models and long videos untested.
- Edits: pass **`-Write`** (since 2026-11-05). Settings `agy-write.json` (no `write_file` deny) + `--sandbox` + `--mode accept-edits`. A `-Dir` inside a git repo runs in a **new worktree** from `HEAD` (branch `agy/<time>`, under `%TEMP%\agy-wt\`), so uncommitted changes in the real checkout are not there; a `-Dir` under `%TEMP%` is edited in place; anything else → exit 2. The footer prints the worktree, branch and `git status`. Claude then reviews the diff (and runs tests), merges/copies what's good, and removes the worktree + branch (the footer prints both commands). Never on the vault/memory directly. Tested only on a toy repo so far (2026-11-05): check the first real `-Write` run closely. Boundaries tested 2026-11-05: writes inside the workspace OK; a write to `C:\Users\lucas\` was denied (`denied=1`, exit 3 since agy then returns no text); a write to `%TEMP%` **is allowed** (official docs: the sandbox grants workspace + system temp dirs), accepted by Lucas. `-Web` and `-Write` don't combine. Only agy's `write_file` tool can write under `-Write`: shell/Python writes are blocked even inside the workspace, so binary output (`.docx` via `python-docx`, `.xlsx`) needs `-Full` under %TEMP% (MedFlow run #31, 2026-11-07).
- Lucas's real logged-in Chrome (tower only, since 2026-11-07, run #37): tell agy to use the tools of the MCP server "playwright" (`browser_navigate`, `browser_file_upload`…), not its built-in browser, which gets a logged-out Chromium. Use `-Full` (any %TEMP% dir) or `-Web` (its `.playwright-mcp/` logs trip exit 5, harmless). Details in `project_agy_delegacion`.
- Builds that must install packages, browse and verify themselves: pass **`-Full`** (since 2026-11-06, Lucas: «restríngele lo menos posible»). Settings `agy-full.json` (sandbox off, no deny) + `--dangerously-skip-permissions`. `-Dir` must be under `%TEMP%`, and it doesn't combine with `-Web`/`-Write`. "Work inside the folder" is only an instruction: shell commands can write anywhere, and only the git check on the three watched repos would notice.
- On builds, don't trust the run's own report (Flash claimed checks that didn't hold in all three 2026-11-06 runs). Ask for a subagent reviewer that sees only the output and a facts file, then check the result yourself. Tight briefs improved correctness but flattened style in that pilot (one run per arm); test method in vault `Agy-Delegation-Log`.
- Let agy do the work itself (Lucas, 2026-11-05): it converts formats on its own (PDF natively, `.docx` via `python-docx` through `run_command`). Claude only writes the prompt and picks which files it sees. No pre-processing that spends Claude tokens. Don't add restrictions "just in case": check the official Antigravity docs or ask Lucas.

## How
```powershell
& "$HOME\.claude\tools\delegar.ps1" -Dir <folder> -Prompt "<task>" [-Model gemini-3.8-flash-medium] [-Effort low|medium|high] [-Timeout 10m] [-Schema <json>] [-Tag <name>]
```
- `-Effort` is optional. Gemini slugs already carry the effort (`gemini-3.8-flash-high`). Claude/GPT models reject `--effort`. If agy fails, the footer shows `[delegar] agy error: …`.
- `-Dir` is agy's workspace: pick the narrowest folder. If the folder mixes things agy shouldn't see (e.g. an exam reserved for a mock), copy only the allowed files into a scratchpad folder and pass that. Long prompts: write them to a scratchpad file and pass `-PromptFile`.
- Model choice: Flash for routine work (~214k tokens ≈ 0.4 pp of the Gemini weekly quota). Opus 4.6 only for one-off probes: one mid-size task (149k tokens) took ~33 pp weekly / ~66 pp 5h of the Claude/GPT bucket (2026-11-05, one run per model). The Opus here runs inside agy's harness, not Claude Code's.
- Ask for a compact answer (a table, a list, or `-Schema` JSON) so reading it back costs few Claude tokens.
- Models: `agy models` lists them. Gemini and Claude/GPT models draw from separate quota buckets.
- Run it with `run_in_background` for long tasks. Lucas watches it live through the `agy-live` mod: a Claude-style status band above the prompt during the run. The full log of the last run (`/agy`, `~/.claude/tools/live/<session id>.log`, since 2026-11-06 one per Claude session) is for Claude; Lucas doesn't need it surfaced. It holds only that session's current run, and logs older than 7 days are deleted.
- While a run is in progress, avoid editing files in the vault, claude-config or claude-skills: the git check can't tell your edits from agy's.
- **One `delegar.ps1` call per tool call, never after a `Start-Sleep`.** The band only attaches if agy starts within 15 s of the call. To re-attach the band to a run already in progress (after a mod reload, or for run 2+ of a chain), run any foreground command containing the string `delegar.ps1`.
- **Research pattern** (cheapest so far, 2026-11-05): 2 independent runs with the same prompt, a fixed JSON schema (claim ids) and verbatim quotes from one official domain. A script diffs the runs and checks that every quote appears on the cited page; template: `Documents/agy-outputs/2026-11-05/verify-boe-quotes.js`. Claude reads only the disagreements.
- **Parallel work inside one run:** `invoke_subagent` works headless (tested 2026-11-05). Subagents run concurrently and can have their own tools and worktree. Fixed overhead is ~140k tokens, so use it only for heavy branches. A custom agent's `model` accepts only `inherit`/`flash`/`pro`; a Claude/GPT opinion needs its own run.
- **Parallel runs from one chat: `-Tag <name>`** (since 2026-11-07). Each tagged run writes its own live log (`live\<session id>-<tag>.log`), and the `agy-live` band shows one dim `✦ <tag> · time · activity` line per tagged run in progress under the main band. Launch every run except at most one with `-Tag`, each in its own background call. Evidence so far: on 2026-11-07 two pairs of Flash-high runs (A+B, then D+E, runs #23–26) ran side by side with separate outputs, using a `CLAUDE_CODE_SESSION_ID` override before `-Tag` existed; `-Tag` itself was tested only with single tiny probes, and the `✦` side lines had not been seen live yet (they load from the next session). Runs from different chats can overlap too; all share the quota, so compare runs by CSV tokens.
- **Verification pattern for extraction/research** (literature checked 2026-11-07, see [[Agy-Delegation-Log]] lessons): (a) vote, then check with a script: N independent runs with the same prompt and schema, plus a script that diffs them and checks every quote against the source; multi-agent debate doesn't reliably beat that (Huang et al. 2023; Smit et al., ICML 2024). Asking the same model to review its own answer adds little without external feedback. (b) A verifier run gets a fresh context: only the source and the claim list, never the extractor's reasoning (Chain-of-Verification idea). Use it to hunt omissions, which voting can't catch; on 2026-11-07 it found 3 omissions and 1 overstated claim. (c) When the quota allows, make the verifier a different model family. (d) A quote check proves only that the quote exists, not that the claim stays within it: on 2026-11-07 a claim added two base types its own (real) quote never named. And items one run has and the other lacks need a grep before merging; that overstated claim was listed as A-only and got merged unchecked.
- For read-only tasks, tell agy in the prompt not to use shell commands (`read_file` only). On 2026-11-07 a needless `(Get-Content x).Length` call hung until the 20 min timeout and turned a complete answer into status ERROR.
- **Claude/GPT (3p) bucket:** when it says «quota reached», it doesn't refresh exactly at the stated reset time. Retry once; if it still fails, drop the run.

## Reading the result
- Exit 0 = usable. 3 = failed/empty (retry once with a simpler prompt, else do it in Claude). 5 = a watched repo changed during the run **and** agy could have done it (it used a shell/write tool, or the run was `-Web`/`-Write`/`-Full`). The footer lists the changed paths either way (since 2026-11-07); when agy used no write-capable tool they're labelled as another chat or a sync, the exit stays 0 and the band stays blue. On exit 5, first check whether the listed files are ones you or another chat edited (memory lives in claude-config, so this happens). Alert Lucas only if a change is unexplained.
- The footer line reports tokens, denied actions and the conversation id (`agy -p ... --conversation <id>` continues it).
- Verify by spot-check (Lucas, 2026-11-05): confirm concrete claims against the source before relying on the output, scaled to the model. Flash outputs get 2–3 checks, because Lucas trusts Flash less, even on high. A stronger model (e.g. Gemini 4 Argon, once available) gets 1–2. Anything that ends up written to the vault still gets full verification.
- Every run is logged to `~/.claude/tools/delegar-log.csv` with tokens and the quota left afterwards (quota measurement). Quota on demand: `agy -p "/usage" --output-format json` (no model call).
- **After each real run, add a row to vault `Conocimiento/IA/Coding-LLMs/Agy-Delegation-Log.md`**: claims checked, errors found, Claude cost (S/M/L) and where the result was used. Save the output and prompt in `Documents/agy-outputs/<date>/`, with a provenance header (model, tokens, conversation id, what was verified). Test runs go in folders named `web*`, `flash1`, `toyrepo`, or under `%TEMP%\agy-wt`. Real runs must never use those names, or they are miscounted as tests.
