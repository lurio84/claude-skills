# Delegar (agy)

Runs `~/.claude/tools/delegar.ps1` (private claude-config repo, with the never-send list). Works on any PC where `agy` is installed and signed in. Evidence and dated tests behind these rules: vault `Agy-Delegation-Log` (§ Evidence behind the delegar skill, and the run table); setup details: private memory `project_agy_delegacion`.

## When
- **Delegate:** reading/summarizing many files, inventories, "find where X is", first-pass review of a repo or document set, extracting facts into a table.
- **Vault edits can go to agy** (`-Vault`, since 2026-11-24, Lucas): notes, sweeps that fix many notes, drafts. Its hooks commit each file as author `agy`, so its work stays traceable. Claude reviews the agy commits listed in the footer (`git show <hash>`) before telling Lucas it's done.
- **Keep in Claude:** memory and repos other than the vault, judgment calls, finance, outward actions, and anything under the never-send list (`~/.claude`, `~/.ssh`; the script exits 2 — don't work around it, ask Lucas). Exception: rules and memories from `~/.claude` may go out as a filtered scratchpad copy (no settings, `.env` or credentials) that passes `mcp__plugin-authoring__scan_secrets`.
- Let agy do the work itself: it converts formats on its own (PDF natively, `.docx` via `python-docx`). Claude only writes the prompt and picks which files it sees. Don't add restrictions "just in case": check the official Antigravity docs or ask Lucas.
- Not for animation QA: Flash reads a local video's content (speech, on-screen text) but misses brief motion and passes defects as clean.

## Modes
| Mode | Use | Constraints |
|---|---|---|
| default | read-only (sandbox + `write_file` deny) | `search_web` gives snippets only; no URL fetch |
| `-Web` | fetch full pages (`curl.exe -sL <url>`) | `-Dir` must be an **empty** fresh scratchpad folder (exit 2 otherwise); anything appearing in it → exit 5. Sandbox off + auto mode: shell can write anywhere, only the git/empty-dir checks notice |
| `-Write` | edits | `-Dir` in a git repo → new worktree from `HEAD` (branch `agy/<time>`, uncommitted changes absent); under `%TEMP%` → in place; else exit 2. Since 2026-11-25 agy's auto mode with `enableTerminalSandbox: false`, but per the Antigravity docs (antigravity.google/docs/settings/, read 2026-11-25: "auto mode turns it on automatically"), auto mode forces the terminal sandbox on, so every command first runs sandboxed and agy retries it outside (see probes below), git writes and dot-folders denied by command regex: it may run servers/tests to self-check (agy tries its sandbox first, then its own check decides what may run outside) (`write_file` denied on `~/.claude` and the vault). Before that, `--mode accept-edits` overrode auto and only `write_file` could write. **Probe 2026-11-25 (Hydrogen Medium, `%TEMP%\agy-probe-auto`): failed at step 1.** The Windows sandbox denied `mkdir` even inside the workspace (`UnauthorizedAccessException`). agy's own pre-tool safety check then blocked the unsandboxed retry and halted the run. So the sandbox was then removed for `-Write` (Lucas OK, same day). **Re-probe without the sandbox, 2026-11-25:** agy still tries the sandbox first, then escapes with its own check. `mkdir`, a background `python -m http.server` and `curl` to localhost all worked, and the server was stopped. **Headless Chrome solved, 2026-11-25 (Hydrogen Medium probes in `%TEMP%\agy-probe-*`):** screenshots work once agy runs the command outside its sandbox. Whether the missing `-Wait` also mattered is an unproven guess: no A/B run without `-Wait` outside the sandbox was made, and the earlier "unsandboxed" probe probably still ran sandboxed first (auto mode). Two recipes work, both only after agy leaves its sandbox on its own (sandboxed: no file, or `PermissionError` on the PNG): `Start-Process chrome.exe -ArgumentList '--headless=new',…,'--screenshot=<abs path>' -Wait -NoNewWindow` with its own `--user-data-dir`, or a Python Playwright script (`playwright.sync_api`, installed with its Chromium). For builds, give agy a `shot.py` that serves the folder on a free port and saves full-page 1440/390 shots plus `scrollWidth` and console errors (copy: `Documents/design-skills-test/shot.py`). With it, a Neon Medium build ran 3 shoot-and-fix rounds, opening the PNGs itself (145k tokens, ~7 min). **Deny probe, same day:** `git commit`, a shell write to a relative `.claude\` folder, a shell write and a `write_file` to `~\.claude\`, and a command naming `SecondBrain` were all refused («Matches user-configured deny rule»), tried once each as literal strings under auto mode + `proceed-in-sandbox`; variants (e.g. `git -C . commit`) untested, and the denies must be re-probed after any config change; a plain `Get-ChildItem` ran. The footer's `denied=` count does not include these refusals. A git repo under `%TEMP%` still takes the worktree route, so it needs at least one commit (exit 2 otherwise). Claude reviews the diff, runs tests, merges, removes worktree + branch (footer prints the commands). Never on the vault/memory |
| `-Vault` | edits in the real vault | `-Dir` anywhere in the vault (the script uses the vault root so agy loads `AGENTS.md` and `.agents/hooks.json`). `agy-vault.json` denies git commit/push/reset/checkout and writes to `.claude`, `.gemini`, `.agents`, `.git`. The hooks commit agy's files as author `agy` with trailers `Agy-Model`, `Agy-Launcher: claude`; already-dirty files it touched stay uncommitted (`Touched-Dirty:`). Exit 5 = something to review (`Touched-Dirty`/`Unlogged` trailers, or a config repo changed). Don't edit the same notes while it runs. Undo: `git revert <hash>` |
| `-Full` | builds that install packages, browse, self-verify | `-Dir` under `%TEMP%`; no sandbox. Snapshot of the 3 watched repos first; undo with `delegar-revert.ps1 -Snapshot <file>` (dry run) → `-Apply` (restores tracked files, also undoes others' later edits: review the list; can't see edits to files that were already untracked) / `-DeleteNew` |

Modes don't combine. Browsing defaults to an isolated browser (Lucas, 2026-11-20). Use his real logged-in Chrome only when the task needs his session, and tell him before launching, because he must accept the extension's connection prompt or the MCP times out. Real Chrome (tower only): copy `Documents/agy-outputs/agy-chrome-mcp_config.json` to `<Dir>/.agents/mcp_config.json`, run with `-Full` (or `-Web`; its `.playwright-mcp/` logs trip a harmless exit 5), and tell agy to use the MCP server "playwright" tools (`browser_navigate`…), not its built-in browser. For pages Claude already has a recipe for (WhatsApp Web), reading them with Claude's own `browser_evaluate` is cheaper.

## How
```powershell
& "$HOME\.claude\tools\delegar.ps1" -Dir <folder> -Prompt "<task>" [-PromptFile <file>] -Model gemini-4-hydrogen-medium|gemini-4-neon-medium|… [-Solo] [-Effort low|medium|high] [-Timeout 10m] [-Schema <json>] [-Tag <name>] [-Web|-Write|-Full]
```
- **Model: routing table (Lucas, 2026-11-24, from benchmarks + quota cost in vault `Agy-Models-Map`). Always pass `-Model`; read `/usage` before a batch.** Cost = relative to Hydrogen Medium, all in the shared Gemini bucket.
  - Trivial lookup/list/format → `gemini-4-hydrogen-low` (0.4×, ≈ Haiku).
  - Extraction, sweeps (**default**) → `gemini-4-hydrogen-medium` (1×, ≈ Sonnet High).
  - First-pass review, extraction needing judgment → `gemini-4-hydrogen-high` (2×, ≈ Opus High).
  - Judgment, synthesis, multi-source research → `gemini-4-neon-medium` with `-Solo` (2.3×, ≈ Sonnet Max).
  - Hard cases where Neon Medium fell short → `gemini-4-neon-high` with `-Solo`, `/usage` checked first (4.5×, ≈ Opus Max).
  - Verifying findings → Opus (Claude subagent, or Opus 5.5 in agy on the small 3p bucket), never a Gemini self-check.
  - **Opus 5.5 in agy, opportunistic (Lucas, 2026-11-24):** before a judgment or verification run, read `agy -p "/usage" --output-format json`. If the `3p-weekly` bucket has room, and especially if it resets within ~2 days with quota unused, use `claude-opus-5-5-medium` (or `-high` for hard cases) instead of Neon. Otherwise Neon. Lucas won't track it: Claude does. One ~350k-token Opus run empties the 3p 5-hour bucket (2026-11-13), so keep Opus runs small.
  - Not used: Hydrogen XHigh, Neon XHigh, Carbon (dominated on cost/score), Argon and Flash 3.8 (removed 2026-11-30).
  - Claude orchestrates every run on one level: no Gemini-led subagents. The script's no-`-Model` default is `gemini-4-hydrogen-medium` (since 2026-11-24). `-Solo` is a no-op for Neon (the lead preamble fires only on Argon), kept for clarity.
- `-Effort` is optional; Claude/GPT models reject it. Use Claude/GPT models (separate small quota bucket) only for probes and verification runs. When that bucket says «quota reached» after its reset time, retry once, then drop the run.
- `-Dir` = narrowest folder. If it mixes things agy shouldn't see, copy only the allowed files to a scratchpad folder. Long prompts → `-PromptFile`.
- Ask for a compact answer (table, list or `-Schema` JSON) and **"final answer only"** (otherwise the lead dumps drafts). Give a hard size cap; agy ignores soft limits.
- Read-only tasks: tell agy not to use shell commands (`read_file` only); a needless shell call can hang until timeout.
- Long tasks: **`-Background` in a foreground call**, never `run_in_background` (the agy-live mod refuses it). The script runs its checks (a block returns exit 2 at once), detaches itself and returns; when agy ends, the mod sends a prompt with the `.out` path (`~/.claude/tools/live/<session id>[-tag].out`: answer, footer, `##agy-exit N`). Lucas watches the `agy-live` band; the live log is for Claude.
- **One `delegar.ps1` call per tool call, never after a `Start-Sleep`** (the band attaches only if agy starts within 15 s). To re-attach the band to a running run, run any foreground command containing `delegar.ps1`.
- Parallel runs from one chat: launch every run except at most one with `-Tag <name>`, each in its own `-Background` call.
- While a run is in progress, don't edit files in the vault, claude-config or claude-skills: the git check can't tell your edits from agy's.
- `invoke_subagent` has ~140k tokens of fixed overhead: use subagents only for heavy branches. A subagent's model is only `inherit|flash|pro` (re-check what `flash` maps to after Flash 3.8 leaves on 11-30); a Claude/GPT opinion needs its own run.

## Patterns
- **Research:** 2 independent runs, same prompt, fixed JSON schema with claim ids and verbatim quotes from one official domain. A script diffs the runs and checks each quote on the cited page (template `Documents/agy-outputs/2026-11-05/verify-boe-quotes.js`). Claude reads only the disagreements, and greps one-run-only items before merging.
- **Verifier:** a fresh-context run that gets only the source and the claim list (never the extractor's reasoning) to hunt omissions and overstatements; a different model family when quota allows. A quote check proves the quote exists, not that the claim stays within it.
- **Builds:** don't trust the run's own report. Use a reviewer that sees only the output and a facts file, then check yourself. For anything with permissions, give the reviewer the real permission data and ask about abuse explicitly.

## Reading the result
- Exit 0 = usable. 3 = failed/empty: retry once with a simpler prompt, else do it in Claude. 5 = a watched repo changed and agy could have done it; first check whether the listed files are ones you or another chat edited (memory lives in claude-config). Alert Lucas only if a change is unexplained. The footer lists changed paths even on exit 0, labelled as another chat or a sync when agy used no write-capable tool. 2 = blocked by the script (never-send list or wrong `-Dir`).
- The footer reports tokens, denied actions, agy's error if any, and the conversation id (`agy -p ... --conversation <id>` continues it).
- **Verify like a Claude subagent (Lucas, 2026-11-24):** agy's answer counts like a subagent summary. Check concrete claims against the source: Hydrogen 2–3 checks, Neon 1–2. Full verification only where a Claude subagent's output would get it too (exam/study material, finance, anything sent to third parties, shipped code); that verification is a fresh-context agy reviewer of another model (Opus 5.5 in agy if the 3p bucket has room, else Neon High; Gemini built it → Claude confirms the critical/major findings only), not Claude re-reading everything. Builds: the run's own report is never trusted; re-run its tests yourself. Log misses in `Agy-Delegation-Log` and tighten this rule if Neon errors slip through (runs #132–138, 2026-11-24: builder claimed «0 partial hybrids» twice, wrong both times; the reviewer caught it).
- **Extraction runs:** ask for `count`, oldest and newest item per source in the schema and check those edges. Spot-checks confirm what came back, not what's missing.
- **A timed-out or partial extraction is discarded and relaunched narrower** (one source per run, ready-made scripts). Never resume it asking for "what you already read": it invents verbatim text.
- Template-driven writing: grep every quoted phrase against the source and read any self-reported "process" section in full; Flash fills every slot, inventing content if needed.
- Check every image agy picked by eye before publishing.

## Logging
- Every run goes to `~/.claude/tools/delegar-log.csv` (tokens, quota left). Quota on demand: `agy -p "/usage" --output-format json` (no model call).
- **After each real run, add a row to vault `Conocimiento/IA/Coding-LLMs/Agy-Delegation-Log.md`**: claims checked, errors found, Claude cost (S/M/L), where the result was used. Save output and prompt in `Documents/agy-outputs/<date>/` with a provenance header (model, tokens, conversation id, what was verified).
- Test runs go in folders named `web*`, `flash1`, `toyrepo`, or under `%TEMP%\agy-wt`; real runs must never use those names.
